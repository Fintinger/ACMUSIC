### 第一阶段：基本框架搭建（2022-04-07 ~ 04-12）

- **04-07** 初始化项目，写好基本路由结构以及用 elementUI 布置基本框架
- **04-08** 部署 API 到 vercel，引入并配置 axios，引入 sass，配置好 banner 部分

### 第二阶段：各种具体功能的实现（2022-04-13 ~ 05-22）

- **04-13** 专辑详情页面，想过用全局事件总线的方式实现，但实际上问题很多。最后参考了 [yesmusic](https://music.qier222.com/) 的方式，利用路由来实现，具体就是通过传递 `params` 或者 `query` 参数的方式实现（我选择后者），再通过[路由的 props 配置](https://www.fintinger.site/p/vue2.0%E5%AD%A6%E4%B9%A0%E5%B0%8F%E7%BB%93/#7%E8%B7%AF%E7%94%B1%E7%9A%84props%E9%85%8D%E7%BD%AE)，实现数据的传递，最后在路由的 `activated` 钩子中进行数据的动态更新。
- **04-15** 所有歌单（不包括歌手榜和赞赏榜）和专辑点击跳转详情逻辑完成，就是给的 api 很奇怪，比如说访问 `/playlist/track/all?id=2399935867&limit=100&offset=3` 应该得到 100 首，然而只得到 99 首……这与 offset 无关，因为有 404 首。还有，这里的 `offset` 参数是"偏移的页数"，不用自定义的 `page` 变量即可做到分批次获取。
- **04-16** 歌手详情页完成，包括基本信息展示，TOP50，热门 MV，专辑等。专辑利用之前完成的逻辑，可点击。此外，还有获取歌手所有歌曲功能。再吐槽一下这个 `offset` 参数，在 `/artist/songs` 这个接口下，`offset` 又变成了"偏移个数"而不是"偏移页数"。。 需要借用 `page` 变量，标注出"偏移页数"再进行分批次获取。
  - 利用[全局事件总线](https://www.fintinger.site/p/vue2.0%E5%AD%A6%E4%B9%A0%E5%B0%8F%E7%BB%93/#%e5%85%a8%e5%b1%80%e4%ba%8b%e4%bb%b6%e6%80%bb%e7%ba%bfglobaleventbus)实现歌单的点击，专辑的点击，歌手的点击，歌手全部歌曲的点击。
- **04-17** 歌曲的播放页完成（仅包括 `fixed` 定位下的那一小条……）！！！又双叒吐槽一下 API，那个获取音乐 URL 的 API `/song/url?id=33894312` 真的啥都获取不到，一般 url 都为 null。。还好，有个莫名其妙的 API：`https://music.163.com/song/media/outer/url?id=id.mp3`，给 audio 标签即可播放。。真好👏🏼 此外，对于 Audio 标签，不用插入到 DOM 树里面，而是利用其自身属性或者方法即可。对于其 `current` 属性的监听，可以利用 audio 标签上的监听事件（不是 document 监听！！）`timeupdate` 或 `canplay` 即可，例如：

```js
//sel===songElement,就是audio标签
this.sel.addEventListener('timeupdate', this._currentTime)
this.sel.addEventListener('canplay', this._durationTime)
```

### 第九波：歌词与键盘修复（11-12）

- **11-12** 用户报了两个问题：歌手页（`/artistDetail?id=1048031`）歌词渲染异常、焦点落在「下一首」上按空格却继续切歌。前者查出来是 `getLyric()` 没有请求守卫——快速切歌时先发的 `/lyric/new` 后到，把上一首的词写进了面板；顺带修了换歌后歌词不归零、加载期闪「纯音乐」、长句被省略号两头截断、yrc 翻译因 `toFixed(2)` 精确匹配而整首丢失。后者是 `.controlsRow` 上那句 `@keydown.space.stop`：事件被就地截停，全局空格收不到，浏览器的 `<button>` 默认行为就把空格当成"再点一次这个按钮"
- 本批修复并入 **v1.4.0** 一起发布（同日还有路由改名，见下一节）
- **11-12 补** 空格又踩了一次：`_onGlobalKeydown` 开头的 `if (e.defaultPrevented) return` 会被浏览器扩展的"平滑滚动"抢跑（捕获阶段 preventDefault），焦点在 `body` 时按空格直接失效、焦点在按钮上却没事。空格分支挪到该判断之前，其他快捷键不变
- **11-12 补** 逐字歌词的"花字"：`wcur` 只在当前行更新，行切走时会把半截进度留在原地（yrc 的字时间还常越过下一行行首），唱过的行于是永久半亮半暗。改成行切换时把过去的行归一到"整行唱完"，同时样式上只让 `p.active` 里的字做 0.45/1 区分；同一天再补一条 `p.active ~ p { opacity: .58 }`，把"唱过的行比未到的亮一档"补回来（兄弟选择器，不加状态）

### 第十波：路由统一与歌手 MV 独立页（11-12）

- **11-12** 全站 URL 收敛成「小写 + 资源名」：`/playlist` `/album` `/artist` `/artist/songs` `/artist/albums` `/search/tracks`；「我的」从 `/user` 挪到 `/me`，`/user?uid=` 给用户详情（选项 A）。三处顺带修掉的结构问题：带子路由的父级（`/explore`、`/search`）原来没有默认子级，直接访问是一排空 tab；`/explore/playlist` 那层纯 `router-view` 容器（`Playlist.vue`）拍平后删除；`/search/` 的尾斜杠去掉。旧地址全部挂 redirect（含九个 `/search/*Res`），另加一条 `beforeEach` 把大小写与尾斜杠规范到 canonical 路径。route name 一律没动，站内跳转全走 `{name}`，所以业务代码只改了 6 处硬编码路径
- **11-12** 歌手页 MV 的「更多」原来是就地展开、一次把几百个 MV 全拉完；改成和全部歌曲 / 全部专辑一样的独立页 `/artist/mvs`（offset 分页、触底续拉）。顺带发现 `mvSize` 这个字段不可信（周杰伦给的是 9），页面索性只报「已加载 N 个」
- **`chore(release): v1.4.0`**

### 第十一波：歌曲随时查看 MV（11-12）

- **11-12** 给「歌曲 → 官方 MV」补入口：播放条红心旁的 `MV` 胶囊、歌曲列表歌名后的 `MV` 标签（一次覆盖歌单 / 专辑 / 歌手 / 每日推荐 / 搜索共 8 个列表页）、全屏播放页「看 MV」、播放队列行内图标、歌曲信息面板的 MV 卡片。关联字段直接用歌曲自带的 `mv`（上游没有「按歌曲查 MV」的接口），缺字段的（私人 FM、刷新恢复的 lite 结构）走 `/song/detail` 补一次并缓存

### 第十二波：播放页右栏等高（11-12）

- **11-12** MV / 视频页右栏「相关推荐」改成与左栏 `video-main` 严格等高：原先靠 JS 量 `headH` 下移、`playerH` 限高，标题与播放器异步出现时首帧量到 0 且不再重算，条目一多就比左栏高出一截。现在用「侧栏 `align-self: stretch` + 卡片绝对定位铺满」把高度完全交给左栏，条目超出走内部滚动；顺带删掉 `sidebarStyle` / `observeLayout` 那套测量代码

### 第十三波：个人主页首屏提速（11-16）
